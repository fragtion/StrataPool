Pool

Several PCs as one: share the requests (each PC runs the whole model), or split one model's layers across them (each runs its own layers, with their experts in its own RAM and VRAM).

–
This PC's role

Where a pool's speed comes from. It never adds the PCs' GPUs together on one word: each new word passes through the model's layers one after another, so the PCs take turns rather than working at once.
  • Share requests adds chats, not speed per chat: every PC runs the whole model on its own, so two chats at once run on two PCs, each at that PC's full speed. A chat stays on the PC that holds its conversation.
  • Split layers can make one chat faster, from memory rather than compute: each PC keeps only its own layers' experts and context, so together their VRAM caches far more of the model. Fewer experts then run on the slow CPU path. A desktop that wrote 21-33 words/s alone wrote 34-44 with a laptop joined. The gain is largest when one GPU caches the model poorly; a slow GPU or network takes some of it back, since every word crosses it.

Several chats at once
On: up to one chat per PC runs at the same time, each PC working on a different one, instead of the second chat waiting for the first. Usually slower: on a desktop + laptop pool two chats together wrote 36-39 words/s against 44 one after the other, and a chat alone ran 17% slower (42 against 51 tok/s): each PC keeps VRAM for the extra chat, so fewer experts are cached, and with a long context each extra chat also locks gigabytes of RAM on every PC, so the laptop holds fewer layers. A shorter context makes it cheaper. Keep it on only if several agents must answer at the same time.
Drafts in several chats
With several chats at once: each chat's window also checks a guessed next word, so a chat can get two words a window. The chats then share one window instead of taking turns on the PCs. On a desktop + laptop pool it was no faster (about 33 words/s for two chats together).
Overlap the PCs
One chat: this PC starts the next window on a guess while the workers run the current one, and undoes it when the guess was wrong. It pays when the workers and the network take most of a window and the guesses are usually right; on a desktop + laptop pool it was 4-6% slower (49 against 51 tok/s with sampled replies).
